3. Preview architecture

preview.html

preview.html — локальный entry-point главной страницы.

Он:

  • подключает home.css;
  • подключает home-mobile.css;
  • подключает popups.css;
  • подключает popups-mobile.css;
  • подключает page-transition.css;
  • загружает pages/home/home.html через fetch;
  • после вставки HTML подключает home.js;
  • после home.js подключает page-transition.js;
  • работает как production sandbox главной страницы.

biography-preview.html

biography-preview.html — локальный entry-point страницы «Биография».

Он:

  • подключает home.css, потому что меню переиспользует систему главной страницы;
  • подключает biography.css поверх home.css;
  • подключает popups.css;
  • подключает popups-mobile.css;
  • подключает page-transition.css;
  • загружает pages/biography/biography.html через fetch;
  • после вставки HTML подключает biography.js;
  • после biography.js подключает page-transition.js.

wedding-preview.html

wedding-preview.html — локальный entry-point страницы «Свадьба».

Он:

  • подключает home.css для общей системы меню;
  • подключает wedding.css для desktop-страницы «Свадьба»;
  • подключает project-reviews.css для общего модуля отзывов;
  • подключает popups.css и popups-mobile.css для общей формы связи;
  • подключает page-transition.css;
  • загружает pages/wedding/wedding.html через fetch;
  • после вставки HTML подключает wedding.js;
  • после wedding.js подключает page-transition.js.

Статичный transition overlay

В preview.html и biography-preview.html должен быть заранее размещён overlay: 

<div class="ip-page-transition is-enter" aria-hidden="true"></div>

Он нужен, чтобы новая страница не успевала дёрнуться до запуска transition JS.

4. Правила работы ChatGPT

Главное правило

ChatGPT всегда присылает:

  • полный готовый файл;
  • или полный готовый блок только если пользователь прямо попросил блок;
  • коммит в конце, если правка относится к проекту.

Строго запрещено

Найди строку и замени...
Нажми Replace All...
Вручную исправь 14 мест...
Остальной код без изменений...
Вставь этот маленький patch...

Разрешено

Полностью замени css/home.css этим кодом
Полностью замени js/page-transition.js этим кодом

Patch policy

Patch допускается только если пользователь явно просит точечный фрагмент. По умолчанию — только полный готовый файл.

Никаких ручных replace workflow. Никаких сокращений. Никаких «фрагмент ниже». Пользователь требует чистые полные файлы.

6. Desktop architecture

Desktop base

1440×800

Desktop logic

Desktop масштабируется по высоте: 

scale = viewportHeight / 800

ВАЖНО

  • desktop НЕ работает через contain;
  • desktop НЕ должен показывать полосы сверху/снизу;
  • разрешён controlled crop по краям;
  • композиция должна сохранять cinematic framing;
  • главная и биография используют одну логику масштабирования по высоте.

Главная

.ip-home-stage{
  width:1440px;
  height:800px;
  transform:translate3d(-50%,-50%,0) scale(var(--ip-home-scale,1));
}

Биография

.ip-biography-stage{
  width:1440px;
  height:800px;
  transform:translate3d(-50%,-50%,0) scale(var(--biography-scale,1));
}

7. Mobile architecture

Mobile base

390×700

Mobile logic

scaleX = viewportWidth / 390
scaleY = viewportHeight / 700
scale = Math.max(scaleX, scaleY)

ВАЖНО

  • mobile всегда должен заполнять экран;
  • никаких нижних пустот;
  • никакого вертикального скролла;
  • mobile CSS хранится отдельно;
  • mobile не смешивать обратно в desktop CSS;
  • сначала доводить desktop, потом делать mobile.

13. Page transitions

Files

css/page-transition.css
js/page-transition.js

Текущий выбранный стиль

Короткий монтажный переход через чёрный экран.
Без blur.

Логика

1. Пользователь кликает по ссылке на другую html-страницу.
2. Страница быстро затемняется в чёрный экран.
3. Выполняется переход на новую страницу.
4. Новая страница проявляется из чёрного экрана.

ВАЖНО

  • Blur в page transition не использовать.
  • Переход должен работать с главной на биографию и обратно.
  • Переход должен работать при browser back/forward.
  • Для browser back/forward обработать pageshow и bfcache.
  • Overlay должен быть в HTML заранее, чтобы не было рывков.
  • Внешние ссылки, tel, mailto и popup triggers не перехватывать.

Не перехватывать ссылки

href="#"
tel:
mailto:
target="_blank"
[data-popup-open]

Текущие параметры перехода

EXIT_DURATION около 280ms
ENTER_DURATION около 380ms
MAX_ASSET_WAIT около 420ms

Browser navigation bugfix

Если пользователь нажимает стрелки браузера назад/вперёд, не должен оставаться чёрный экран. Для этого в page-transition.js обязательно есть: 

window.addEventListener('pageshow', function(event){
  if(event.persisted){
    resetOverlay();
  }
});

window.addEventListener('popstate', function(){
  window.setTimeout(function(){
    resetOverlay();
  }, 0);
});

21-B. Жёсткие правила по формату ответов ChatGPT

ПРАВИЛО ДЛЯ ВСЕХ СЛЕДУЮЩИХ ЧАТОВ:

Если пользователь просит файл

Нужно дать полный файл от первой до последней строки.

Если пользователь просит несколько файлов

Если пользователь просит коммит

Давать только готовую фразу коммита без лишних пояснений.

Add mobile Safari and Android safe biography behavior

Найди этот блок и замени...

Остальной код без изменений...
Вот patch...
Вот только изменённый фрагмент...

Исключение

Фрагмент можно дать только если пользователь прямо попросил фрагмент, короткую вставку или точечный блок. Во всех остальных случаях — полный файл.

21-C. Правила разделения desktop и mobile

КРИТИЧЕСКОЕ ПРАВИЛО:

21-E. Актуальные правила popup после финальной настройки

Popup должен быть общим

  • Popup используется на главной странице.
  • Popup используется на странице «Биография».
  • Popup будет использоваться на будущих страницах, включая «Свадьба».

Финальная анимация popup

  • Blur фона начинает появляться сразу после клика.
  • Popup-card появляется с небольшой задержкой после старта blur.
  • Финальная точка появления popup-card визуально синхронизирована с финальной точкой blur.
  • Анимация уже принята пользователем.
  • Не ускорять и не замедлять её без прямого запроса пользователя.

Финальное масштабирование popup

  • Масштабируется весь popup-card как единый макет.
  • При уменьшении viewport уменьшается не только изображение, но и текст.
  • Поля ввода уменьшаются вместе с карточкой.
  • Кнопка уменьшается вместе с карточкой.
  • Чекбокс и policy-текст уменьшаются вместе с карточкой.
  • Desktop popup использует базовый макет 790×530.
  • Mobile popup использует базовый макет 350×654.

Техническое решение popup scaling

Для масштабирования всего содержимого popup используется container-type:inline-size на .ip-popup-card и единицы cqw для координат, размеров и типографики.

Safari / Android / современные браузеры

  • Анимации должны работать в современных Chrome, Safari и Android-браузерах.
  • Для Safari обязательно сохранять -webkit-backdrop-filter.
  • Для плавности использовать translate3d, backface-visibility, will-change там, где это уже применено.

23. Safari-safe animation rules

КРИТИЧЕСКОЕ ПРАВИЛО:
Все новые анимации и hover-эффекты должны настраиваться с учётом Safari.

Главная проблема

Safari и часть Chromium-браузеров могут перерастеризовывать текст, если одновременно используются:

  • transform на контейнере с текстом;
  • backdrop-filter или filter;
  • масштабирование scale();
  • мелкая типографика;
  • полупрозрачные слои поверх текста.

Запрещено

  • Не анимировать текстовые контейнеры через transform, если рядом используется blur/backdrop-filter.
  • Не использовать решения, которые дают заметное дрожание или изменение жирности текста.
  • Не добавлять hover-подъём через transform на контейнер с текстом, если это вызывает блюр.
  • Не анимировать backdrop-filter без необходимости.

Предпочтительно

  • opacity;
  • visibility;
  • box-shadow;
  • отдельный декоративный слой;
  • анимация тени вместо движения текстового слоя;
  • Safari-safe подход без перерастеризации текста.

Для карточек и кнопок

  • Если нужен hover-эффект, сначала пробовать тень.
  • Если нужен подъём, не двигать текстовый слой.
  • Если текст начинает дрожать, остановиться и выбрать более безопасный эффект.

# IVAN PERTSEV SITE — WORKFLOW RULES

Версия: V1
Назначение: использовать как постоянную инструкцию для работы над проектом сайта Ивана Перцева в любых новых чатах.

---

# 1. ОСНОВНОЙ ПРИНЦИП РАБОТЫ

Работа ведётся только через:

* GitHub
* GitHub Pages
* Tilda T123
* разделённые файлы HTML/CSS/JS

Запрещено:

* хаотично править код кусками;
* давать инструкции «найди и замени»;
* присылать неполные фрагменты кода без контекста;
* ломать существующую логику анимаций и адаптива.

Всегда сохранять стабильность проекта.

---

# 2. СТРУКТУРА ПРОЕКТА

Структура репозитория должна быть такой:

assets/
fonts/
icons/
img/

backup/
home/

css/
js/
pages/
home/

docs/
README.md

---

# 3. ПРАВИЛА РАБОТЫ С КОДОМ

Всегда предоставлять:

* полный готовый код файла;
* без инструкций «замени строку»;
* без частичных CSS-блоков;
* без сокращённых примеров.

Если меняется:

* home.css → присылать полный home.css;
* home.js → присылать полный home.js;
* home.html → присылать полный home.html.

В коде обязательно оставлять:

* текстовые комментарии;
* понятные секции;
* пояснения критических мест.

Пример:

/* =========================================================
ПОДЗАГОЛОВОК
========================================================= */

---

# 4. РАБОТА С TILDA

Tilda используется только как shell.

В T123 хранится только:

* подключение CSS;
* fetch HTML;
* подключение JS.

Весь основной код хранится только в GitHub.

---

# 5. ОБЯЗАТЕЛЬНОЕ ПРАВИЛО CACHE VERSION

После любого изменения:

* home.css
* home.js
* home.html

обязательно менять версию:

?v=18
?v=19
?v=20
и т.д.

Иначе изменения могут не примениться из-за кэша GitHub Pages и Tilda.

Всегда предоставлять полный обновлённый код T123 после изменения версии.

---

# 6. ПРАВИЛА РАБОТЫ С T123

Всегда присылать полный код блока T123.

Никогда не писать:

* «замени строку»;
* «найди это»;
* «вставь сюда».

Только полный готовый код.

---

# 7. АНИМАЦИИ

Главный приоритет:

* отсутствие дёрганий;
* отсутствие layout shift;
* отсутствие перекрытия текста;
* стабильная работа во всех популярных браузерах;
* стабильная работа в Safari.

Запрещено:

* ломать существующую анимацию;
* менять easing без необходимости;
* менять transform-origin без объяснения;
* использовать нестабильные хаки.

---

# 8. TYPOGRAPHY

Главная цель:

максимально близкое соответствие Figma-макету.

Особенно важно:

* позиционирование имени;
* позиционирование фамилии;
* хвост буквы «Р»;
* расстояние до подзаголовка;
* baseline текста;
* letter-spacing.

Любые правки typography должны:

* не ломать анимацию;
* не вызывать перекрытия;
* не вызывать скачков.

---

# 9. BIG SCREEN RULES

Сайт должен корректно работать:

* 1440×800;
* ultrawide мониторы;
* большие desktop-разрешения.

Важно:

* лицо не должно обрезаться;
* композиция должна сохраняться;
* масштабирование должно быть плавным.

---

# 10. BURGER MENU

Бургер обязан:

* корректно отображаться на всех разрешениях;
* не иметь артефактов;
* не показывать третью линию;
* не ломаться в Safari.

Запрещено использовать:

* нестабильные псевдоэлементы;
* лишние box-shadow;
* browser default styles.

---

# 11. BACKUP SYSTEM

Перед крупными изменениями обязательно:

создавать backup.

Пример:

backup/home/home-v17-stable.html
backup/home/home-working.html
backup/home/home-current.html

Commit examples:

* Create V17 stable backup
* Save working home version
* Backup current home page

---

# 12. ПРАВИЛА COMMITS

Commit messages должны быть:

* короткими;
* понятными;
* на английском.

Примеры:

* Fix subtitle overlap
* Improve burger rendering
* Stabilize text animation
* Lower subtitle by 15px

---

# 13. ПРАВИЛА РАБОТЫ CHATGPT

ChatGPT обязан:

* помнить текущую архитектуру проекта;
* не возвращаться к inline-коду;
* не предлагать хаотичные правки;
* не предлагать image generation вместо правки кода;
* не ломать существующую структуру.

ChatGPT обязан:

* думать перед изменением;
* анализировать последствия;
* учитывать предыдущие проблемы проекта.

---

# 14. КАК ПРОДОЛЖАТЬ РАБОТУ В НОВОМ ЧАТЕ

В новый чат отправлять:

1. ссылку на GitHub;
2. этот документ;
3. текущую задачу.

После этого ChatGPT обязан:

* продолжать работу по этим правилам;
* использовать существующую архитектуру;
* не предлагать старый хаотичный подход.

---

# 15. РЕКОМЕНДУЕМЫЙ WORKFLOW

Правильная схема работы:

1. Создать backup.
2. Внести изменения в GitHub.
3. Commit.
4. Sync.
5. Обновить cache version.
6. Обновить T123.
7. Publish Tilda.
8. Ctrl + F5.
9. Проверить desktop.
10. Проверить ultrawide.
11. Проверить Safari.

---

# 16. ГЛАВНОЕ ПРАВИЛО

Стабильность проекта важнее скорости.

Лучше:

* одно качественное изменение;
  чем:
* пять хаотичных правок.

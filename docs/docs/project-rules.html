Назначение документа: зафиксировать актуальное состояние проекта, правила работы с кодом, структуру файлов, адаптацию desktop/mobile и порядок дальнейшей разработки.

Актуальный статус: главная страница находится в production build состоянии. Desktop и mobile разделены на отдельные CSS-слои.

2. Правила работы с кодом

Главное правило

ChatGPT всегда должен присылать полный готовый файл или готовый patch-блок, который можно вставить целиком в конец файла.

Запрещено

Найди строку и замени её

Разрешено

Полностью замени css/home-mobile.css на этот код

Исключение: patch допускается только если он целиком вставляется в конец файла и не требует ручного поиска.

3. Версионирование в Tilda

В Tilda все внешние файлы подключаются через ?v=, чтобы сбрасывать кэш.

Текущая логика версий

home.css?v=64
home.html?v=64
home.js?v=65
home-mobile.css?v=25

Правило обновления

Изменили home.css        → повышаем home.css?v=
Изменили home-mobile.css → повышаем home-mobile.css?v=
Изменили home.html       → повышаем home.html?v=
Изменили home.js         → повышаем home.js?v=

Если нужно привести desktop core к единому значению, можно синхронизировать:

home.css
home.html
home.js

Mobile version можно вести отдельно.

6. Desktop адаптация

Базовый макет

1440×800

Текущая логика desktop

Desktop масштабируется по высоте:

scale = viewportHeight / 800

Это значит:

  • экран всегда заполнен по вертикали;
  • чёрные полосы сверху и снизу не появляются;
  • композиция остаётся фиксированной как в макете;
  • по горизонтали могут слегка обрезаться края;
  • контентная зона сохраняет art-direction.

Почему так сделано

Главная страница — cinematic/art-directed hero. Для неё важнее сохранить композицию, чем показывать весь фон целиком на любых пропорциях экрана.

Поведение на разных экранах

16:9    → почти полное совпадение с макетом
16:10   → заполняет высоту, края могут слегка обрезаться
21:9    → допустимо большее обрезание краёв
32:9    → нестандартный случай, допускается сильный crop

Важно

Desktop не должен масштабироваться через contain. Иначе появляются полосы сверху/снизу и ломается композиция.

7. Mobile адаптация

Базовый макет

390×700

Текущая логика mobile

Mobile масштабируется как cover:

scaleX = viewportWidth / 390
scaleY = viewportHeight / 700
scale = Math.max(scaleX, scaleY)

Это значит:

  • мобильный макет всегда заполняет экран;
  • не должно быть нижнего пустого пространства;
  • не должно быть вертикального скролла;
  • композиция остаётся как в макете 390×700;
  • на разных смартфонах возможен небольшой crop по краям.

Mobile viewport

В mobile используется:

height:100dvh;
min-height:100dvh;

Это нужно для Android Chrome, Safari iOS и мобильных браузеров, где обычный 100vh может давать нижний зазор.

8. Typography rules

Desktop title

font-family: Benzin
font-size: 88px
line-height: .85

Mobile title

font-family: Benzin
font-size: 62px
line-height: .81
letter-spacing: 0

Mobile typography issues

На Android и iOS кастомный шрифт Benzin может рендериться иначе, чем в desktop DevTools. Поэтому для mobile увеличены высоты строк и добавлен запас:

.ip-title-line-first  → height:74px
.ip-title-line-second → height:96px
.ip-title-line span   → height:104px; padding-top:8px

Это защищает текст от обрезания сверху и справа.

12. Hover rules

Hover для desktop соцсетей работает через opacity двух слоёв:

::before → обычная иконка
::after  → hover-иконка

Не делать hover через замену background-image, потому что это вызывает мигание в Safari и на Retina.

17. Что нельзя делать

  • Не смешивать mobile CSS обратно в home.css.
  • Не менять desktop при правках mobile без отдельной команды.
  • Не менять mobile при правках desktop без отдельной команды.
  • Не использовать find and replace в ответах ChatGPT.
  • Не генерировать изображения, если пользователь просит править код.
  • Не менять рабочие версии целиком, если проблема решается patch-ом.

19. Важное резюме для нового чата

Проект — сайт Ивана Перцева на Tilda + GitHub Pages. Главная страница реализована кодом через T123/fetch. Desktop и mobile разделены:

home.css        → desktop core
home-mobile.css → mobile overrides
home.js         → scale/menu/accordion logic
home.html       → structure

Desktop использует fixed composition 1440×800 и масштабируется по высоте. Mobile использует fixed composition 390×700 и масштабируется как cover. Главная работает на layered images: base background, glow background, portrait, overlay, content/menu.

Главное правило работы: присылать только полный готовый код файла или целиком готовый patch в конец файла. Не предлагать ручные замены строк. Не генерировать изображения при задачах по коду.

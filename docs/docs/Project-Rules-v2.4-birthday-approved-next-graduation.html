1. Текущий статус проекта

APPROVED STABLE:
На текущий момент завершены и утверждены в desktop и mobile:
  • Главная;
  • Биография / Обо мне;

Утверждённые страницы считаются замороженными. Их нельзя менять без прямого запроса пользователя. Это относится к desktop, mobile, меню, popup, page transition, видео, галереям, отзывам, lightbox, scroll-top, CTA и общей композиции.

3. Правила работы ChatGPT

По умолчанию ChatGPT обязан

  • сам анализировать предоставленные файлы;
  • сам находить причину ошибки;
  • сам собирать итоговое решение;
  • давать полный готовый файл целиком;
  • для нескольких файлов давать готовый архив с правильной структурой;
  • после проектной правки давать commit message в отдельном копируемом code block.

Строго запрещено

Найди строку и замени...
Добавь это в конец...
Остальной код без изменений...
Вот patch...
Вот только изменённый фрагмент...
Поменяй вручную 14 мест...

Исключение

Фрагмент можно дать только если пользователь прямо попросил фрагмент, короткую вставку или объяснение без готового файла.

Правило после двух неудачных попыток

Если изменение не сработало после двух попыток, запрещено продолжать угадывать.

В этом случае ChatGPT обязан:

  • остановить правки вслепую;
  • запросить все связанные файлы;
  • сравнить рабочую эталонную страницу и проблемную страницу;
  • найти фактический источник управления элементом: CSS, JS, HTML, inline-style или конфликтующие override-блоки;
  • только после анализа дать один готовый комплект.

Commit style

Коммит всегда давать в копируемом блоке:

Create graduation desktop page layout

Не использовать:

fix
fix2
newfix
finalfix
test
update

5. Правила файлов и версий

Каждый HTML/CSS/JS файл обязан содержать в начале:

Версия
ИЗМЕНЕНИЯ

Пример CSS-заголовка

/*
==================================================
BIRTHDAY MOBILE CSS

Версия: birthday-mobile-css-006-opened-height-sync

ИЗМЕНЕНИЯ:
- файл основан на birthday-mobile-css-005-review-hint-40px-gap
- раскрытая высота CSS-контейнеров синхронизирована с JS
- закрытая страница, галерея, отзывы, меню и popup не изменялись
==================================================
*/

Правило имён файлов при передаче

  • Для скачивания использовать versioned filename: birthday-mobile-css-006-....
  • В инструкции всегда указывать, какой проектный файл заменить: css/birthday-mobile.css.
  • JavaScript-файлы для проекта Ивана Перцева всегда отдавать ZIP-архивом.
  • Внутри ZIP JavaScript должен иметь проектное имя файла, например birthday-mobile.js, а не временное имя.

6. Общая архитектура страниц

Desktop base

1440×800
  • Desktop-композиция собирается как fixed stage.
  • Масштабирование desktop идёт по высоте viewport.
  • Controlled crop по краям допустим.
  • Desktop и mobile не смешиваются в одном CSS без необходимости.

Mobile base

390×700
  • Mobile-страницы длинные и скроллятся вертикально, если это сервисная страница.
  • Mobile использует отдельный CSS и отдельный JS там, где уже принята такая архитектура.
  • Масштабирование mobile: scale = Math.max(viewportWidth / 390, viewportHeight / 700).
  • Высота mobile-страницы может задаваться и CSS, и JS. При правке высоты обязательно проверять оба места.
Нельзя менять desktop при mobile-правках и нельзя менять mobile при desktop-правках.

МЕНЮ УТВЕРЖДЕНО.
Не менять меню без прямого запроса пользователя.
  • Общее меню переиспользуется на всех страницах.

10. Mobile rules после страницы «День рождения»

Mobile gallery

  • Мобильная галерея проектируется отдельно от desktop.
  • Размеры фотографий не подбирать на глаз.
  • Пользователь заранее утверждает размеры каждого слота.
  • Отступ между фотографиями по умолчанию — 10px.
  • Левый/правый отступ от края по умолчанию — 10px.
  • Порядок фотографий фиксируется отдельной схемой слотов.
  • Если фотография меняется местами, проверять не только CSS-размер, но и порядок изображений в HTML.

Mobile reviews

  • Отзывы отображаются горизонтальным свайпером.
  • Стиль и поведение брать с Corporate Mobile.
  • Текст отзывов выравнивается по левому краю.
  • Popup-отзывы используют approved-логику предыдущих страниц.
  • Если переносы текста в миниатюрах и popup отличаются, править оба места.

Подсказка галереи и ScrollTop

  • Подсказка «Листайте для просмотра» на mobile располагается после блока отзывов.
  • Расстояние от нижнего края отзывов до подсказки — 40px, если пользователь не указал другое.
  • Расстояние между подсказкой и стрелкой ScrollTop настраивается отдельно.
  • Расстояние от стрелки ScrollTop до нижнего края страницы — 40px, если макет не требует другое.
  • Перед правкой положения стрелки определить, чем она управляется: CSS bottom, CSS top, JS-высотой страницы или конфликтующим override-блоком.

Высота mobile-страницы

Нельзя менять высоту страницы случайным подбором значений.
  • Если высота страницы управляется через JS, проверить stageHeightClosed и stageHeightOpened.
  • Если высота страницы управляется через CSS, проверить height, min-height и CSS-переменные.
  • Если используется scale-переменная, CSS и JS должны быть синхронизированы.
  • Если в файле несколько override-блоков с одинаковыми селекторами, выяснить, какой блок побеждает последним.
  • После изменения высоты проверять закрытое и раскрытое состояние отдельно.

Mobile typography

  • Не оставлять висящие предлоги, союзы и короткие слова в конце строки.
  • Если desktop и mobile требуют разных переносов, использовать отдельные текстовые блоки.
  • Не ломать desktop-текст ради mobile-переносов.

11. Видео

  • Использовать Kinescope iframe.
  • Использовать poster-layer перед видео.
  • Autoplay muted loop сохранять там, где это уже реализовано.
  • Не использовать агрессивный overscan iframe без необходимости.
  • Не ломать сетку страницы ради edge-to-edge видео.
  • Если видео работает стабильно, не возвращаться к экспериментам без прямого запроса пользователя.
  • Для новых страниц обязательно запросить новую Kinescope-ссылку и poster.

13. Safari-safe animation rules

Все новые анимации и hover-эффекты должны быть Safari-safe.

Запрещено

  • Анимировать текстовые контейнеры через transform, если рядом используется blur/backdrop-filter.
  • Использовать решения, которые дают заметное дрожание или изменение жирности текста.
  • Добавлять hover-подъём через transform на контейнер с текстом, если это вызывает блюр.
  • Анимировать backdrop-filter без необходимости.

Предпочтительно

  • opacity;
  • visibility;
  • box-shadow;
  • отдельный декоративный слой;
  • анимация тени вместо движения текстового слоя;
  • Safari-safe подход без перерастеризации текста.
